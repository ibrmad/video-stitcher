**Goal:** the app opens real work without the command line. You add each
camera's videos, remove and reorder them, then calibrate (with progress
and Cancel) or load a calibration. The preview opens once both cameras and
a calibration are set. Recent sessions, dropped files and the next-step
card all drive the same model.

**Spec:** DESIGN.md row 3; PARITY.md Module 3; docs/slint-inventory.md
§2.2, §2.7, §7 (auto-calibration); reco-gui `main.rs` 2493–2620 and
`handle_calibration_result`.

## Decisions (rulings made up front)

- **Recent sessions, not three lists.** Module 0's approved design has a
  Recent menu of camera pairs ("GX010120 + GX010092"). One click restores
  both cameras' files and the calibration. This replaces the Slint dialog's
  three columns (left videos, right videos, calibrations). It keeps 8
  sessions, newest first, with "Clear recent files". (New; parity's "click
  loads, Clear all" holds.)
- **GoPro order (New).** A GoPro file is GXccnnnn (chapter cc of recording
  nnnn), so a name sort interleaves recordings. Each batch of added files is
  ordered by recording, then chapter; other names sort by name. Files
  already in the list keep their order. A file already in the list isn't
  added twice. Only mp4/mov/avi/mkv are accepted (case-insensitive).
- **A saved calibration is found (New).** When both cameras are set and
  `{first left stem}_calibration.json` sits beside the first left file (where
  auto-calibrate saves it, as Slint did), it loads, with an info toast.
- **Calibration input (parity).** Calibration uses the first file of each
  camera. Recalibrating starts at the preview's time when that falls within
  both first files, else at 0. A recalibration keeps the current lens (the
  calibration's camera params).
- **Calibration output (parity).** Saved as `{stem}_calibration.json` beside
  the first left file, written atomically, and pushed to the recent session.
  Toasts:
  - confidence < 0.5: "Low calibration confidence" (warn);
  - a Fallback profile: "Using a generic lens profile" (warn);
  - success: "Calibrated" (info, "{matches} matched points · {file}").
- **Changing files** (add, remove, reorder, clear) cancels a running
  calibration, and reopens the preview when both cameras and a calibration
  remain. Clearing the calibration (the chip's ×) closes the preview.
- **Checks can't drive a native dialog.** `RECO_DESKTOP_DIALOG_ANSWERS=<json
  file>` answers a dialog from the file's `{"left"|"right"|"calibration":
  [paths]}` entry instead of opening it, through the same action path as a
  real pick.
- **Drops:** videos dropped on a camera row go to that camera. Dropped
  elsewhere, they go to the first camera with no videos; if both cameras
  have videos, nothing is added and a toast says to drop onto a camera row.
  A dropped `.json` loads as the calibration.

   Vec<PathBuf>, calibration: Option<PathBuf>}`, with:

   - `files(camera)`, `input(camera) -> Option<InputPath>`, `stage() -> Stage {NoVideos, OneCamera(Camera), Cameras, Ready}`;
   - `sibling_calibration() -> Option<PathBuf>`;
   - `is_video`, `video_order`, and `route_drop(paths, over) -> DropPlan`.

   Tests:
   - GoPro order;
   - duplicates and non-videos skipped;
   - move and remove bounds;
   - stages;
   - the sibling name;
   - drop routing (row, first empty camera, both full, JSON).
2. **Settings: recent sessions.** `RecentSession {left, right, calibration}`

   `push_recent` (dedupe on left+right, newest first, at most 8);

   - `CalibrationJob::start(left, right, lens: Option<(CameraParams, CameraParams)>, options, waker)`, with `cancel()` and `try_event() -> Option<CalibrationEvent>`;
   - events `Progress {step, of, text}`, `Done(CalibrationDone {path, confidence, matches, fallback_lens, frames_used})`, `Failed(String)`, `Cancelled`.

   The JSON is saved atomically. Tests:
   - options → config mapping;
